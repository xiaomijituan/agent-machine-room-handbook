# 第 7 章证据：两台设备在同一个 tailnet 里（2026-10-09）

**这一份记的是什么**：本机（Windows）与一部随身 Android 设备在同一个 tailnet 内的状态，
以及同一轮里本机那个每 2 秒写一行的进程有没有停。

**这一份里没有的是什么（很重要）**：`tailscale ping` 那几批逐包输出**当时没有写成文件**。
所以正文里那些 pong 的毫秒数（`1.353s`、`461ms`、`4.882s`、`timed out`、首包 `2.629s` 等）
**取自当场记录，原始输出未入库**，证据等级按 B 算，不按这份文件的 A 算。要升成 A，
得在同一组条件下重跑并把输出直接写进文件（补测项记在 OpenSpec 的 6.4）。

## 一、`tailscale status --json` 的掩码摘录（这份是 A：文件在此）

```
Self.HostName        = <本机设备名>
Self.DNSName         = <本机设备名>.<tailnet 域名>
Self.Relay           = sfo    # 本机自己挂的中继代号
Peer[<节点公钥>].HostName = <对端设备名>
Peer[...].DNSName         = <对端设备名>.<tailnet 域名>
Peer[...].Relay           = tok    # 对端那一条显示的中继代号
Peer[...].Online          = true
Peer[...].LastSeen        = 0001-01-01T00:00:00Z
Peer[...].LastHandshake   = 0001-01-01T00:00:00Z
Peer[...].RxBytes         = 0
Peer[...].TxBytes         = 0
CurrentTailnet.Name  = <tailnet 账号>
被 ping 的 tailnet 地址 = 100.x.x.x
```

**这份摘录能定下来的结论**：对端在线、能对上，但它显示的中继是代号 `tok`，
本机自己挂的中继是代号 `sfo`。`tailscale status` 不带 `ping` 那种逐包路径行，
所以「对端活跃」这四个字本身推不出「直连还是绕中继」——要看 `relay` 这一栏，或者去跑 `tailscale ping`。
**代号对应的城市名不在这些输出里，本章不猜。**

## 二、断连那一轮里本机进程的写入（这份是 A：文件在此）

原始文件 47 行，每行一次写入，间隔约 2 秒。头两条与最后两条：

```
tick 1 2026-10-09T06:42:43.904Z
tick 2 2026-10-09T06:42:45.913Z
...
tick 46 2026-10-09T06:44:14.288Z
tick 47 2026-10-09T06:44:16.290Z
```

时间戳跨度：首行与末行相差约 90 秒。

**这条结论的分寸**：它只证明「这台机器上那个每 2 秒写一行的进程，在本机虚拟网卡被关掉的那段时间里没停」。
它不证明「agent 的活在断网之后还活着」——那要掐的是对端那一侧的网，见第 6 章的做法。

## 涂改了哪些

本机设备名、对端设备名、两个 `*.ts.net` 域名、tailnet 账号（一个邮箱形态的标识）、节点公钥、
用户号、tailnet 地址（按 `100.x.x.x` 格式整段替换，不是按具体地址替换）。
中继代号 `tok`、`sfo` 保留：那是公开基础设施的代号，
也是这一章要引用的东西。
