# 第 8 章 · 国内网络环境下的差异卡片

| 操作                                                | 你会看到什么                                                | 坑在哪                                                                                                      |
| --------------------------------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `git push`（直连 GitHub，不挂代理）                 | 有时直接 `SSL_ERROR_SYSCALL` 或 `Empty reply`，重试几次才过 | 推送失败**不代表关口红**：那两条是网络错误，不是 `Bypassed rule violations`。分不清就会去改配置，而配置没错 |
| 看 GitHub Actions 的作业日志页面                    | 页面能开，日志刷得慢，偶尔整段空白                          | 关口红没红要看作业头部状态，不要凭"日志没刷出来"判定通过                                                    |
| CI 里 `npx playwright install --with-deps chromium` | 在 GitHub 的机器上跑，下载浏览器不经过你家宽带              | **你被墙不影响 CI 那台机器**；把两边的失败混在一起，会误以为"CI 也挂了"，其实本地网络才是变量               |
| `npm ci`（CI 上）与 `npm install`（本机）           | CI 用官方源能装完；本机走官方源很慢，换成国内镜像快很多     | 镜像只解决"装得慢"，不解决"版本不一致"。锁文件（`package-lock.json`）才是关口输入一致的前提                 |

一句提醒：这一章所有量到的东西都发生在本机和 GitHub 上，**没有一条依赖国内网络的特例**。
上面四条里只有第一条和第三条是本机实测过的（代理时开时关，同一句 `git push` 结果会变），
第二条和第四条是操作感受，没做过对照，别当结论用。
