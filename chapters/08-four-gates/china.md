# 第 8 章 · 国内网络环境下的差异卡片

| 操作                                                | 你会看到什么                                                        | 问题所在                                                                                                                                                                 |
| --------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `git push`（直连 GitHub，不挂代理）                 | 有时直接返回 `SSL_ERROR_SYSCALL` 或 `Empty reply`，重试几次才能成功 | 推送失败**不代表关口未通过**：`SSL_ERROR_SYSCALL` 与 `Empty reply` 是网络错误，不是 `Bypassed rule violations`。无法区分这两类信息时，人会去修改配置，而配置本身没有错误 |
| 查看 GitHub Actions 的作业日志页面                  | 页面能够打开，日志加载缓慢，偶尔出现整段空白                        | 判断关口是否通过，要看作业头部的状态；不能凭"日志没有加载出来"判定通过                                                                                                   |
| CI 里 `npx playwright install --with-deps chromium` | 在 GitHub 的机器上运行，下载浏览器不经过家庭宽带                    | **本机的网络访问受阻不影响 CI 那台机器**；把两端的失败混为一谈，会误以为"CI 也失败了"，实际上本机网络才是变量                                                            |
| `npm ci`（CI 上）与 `npm install`（本机）           | CI 使用官方源能够装完；本机使用官方源很慢，改用国内镜像后快很多     | 镜像只解决"安装得慢"，不解决"版本不一致"。锁文件（`package-lock.json`）才是关口输入一致的前提                                                                            |

一句提醒：第 8 章所有测量过的内容都发生在本机和 GitHub 上，**没有一条依赖国内网络的特例**。
上面四条里只有第一条和第三条是本机实测过的（本机代理的开关状态不固定，同一条 `git push` 的结果
会变化），第二条和第四条是操作感受，没有做过对照实验，不能当作结论引用。
