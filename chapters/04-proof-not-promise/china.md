# 国内网络差异 · 第 4 章

这一章跟"墙"没关系。国内这边多出来的是两类：AI 响应慢导致输出被截，以及 Windows 上的行尾。

## 卡 1 · 复制给 AI 的日志，先确认行尾

**命令**：

```bash
git ls-files --eol <文件路径>
```

**实测到的**：同一台机器、同一个仓库、`core.autocrlf = true`：

```
i/lf    w/crlf  attr/   AGENTS.md
i/lf    w/lf    attr/   CONTEXT.md
i/lf    w/lf    attr/   README.md
```

**坑**：

- **别用一条通用警告推断所有文件。** 我们错过一次：看到 `LF will be replaced by CRLF` 就以为本机文件都是 CRLF，结果同仓库里两种行尾并存。
- 判断某个文件的真实行尾只能查它自己。字节里有没有 `0d`，或者 `git ls-files --eol` 的 `w/` 字段。
- **AI 按行匹配文本时，带 `\r` 的行容易匹配不上。** 这条我们**没在本机复现**，列在这里是提醒，不是结论。

## 卡 2 · 响应慢的时候，别只看最后一屏

**症状**：网络慢或模型响应慢时，长输出会被分页、会被截屏截断，你复制到的常常是**最后几行**。

**办法**：让命令把完整输出写进文件，再读文件。

```bash
npm test > build.log 2>&1; tail -40 build.log
```

**坑**：只贴末行"12 passed"当证据是不够的——**末行可以由任何一条命令产生，包括跑错目标的那一条**。要能看到跑了哪些文件、几个用例。这条不需要网络，但国内更容易撞上，因为慢会让你懒得重跑。

## 卡 3 · 让 AI 交证据时，把"落到文件"写进那句话

**可以直接抄的一段**：

```
改完后给我：改动的文件清单、你跑的命令、该命令的完整输出。
把完整输出同时写进 build.log，并告诉我文件路径。
```

**坑**：贴在回复里的输出会被截、会在复制时丢行。落到文件里，你随时能自己再看一遍，AI 也不能事后改口径。
