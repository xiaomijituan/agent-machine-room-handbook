# 国内网络差异 · 第 2 章

这一节只放两类东西：**我们在这台机器上测量过的**，和**明确标着"还没有测量"的**。整章正文本来就是讲国内网络，所以这一节的分工是：正文讲结论和实验，这里放可以直接抄去跑的命令卡片，以及每条命令在国内容易触发的故障。

## 卡 1 · 登录能不能通：先量，再决定要不要挂代理

**命令**：

```bash
curl -s -o /dev/null --max-time 10 -w "http=%{http_code} dns=%{time_namelookup}s total=%{time_total}s\n" https://controlplane.tailscale.com
```

**我们看到的**：

```
https://api.tailscale.com          http=302 dns=0.014s total=0.503s
https://login.tailscale.com        http=302 dns=0.009s total=0.502s
https://controlplane.tailscale.com http=302 dns=0.009s total=0.525s
```

**容易出错的三件事**：

- `http=302` 是**正常**的：302 表示"请去登录页"的跳转，看到 302 不要以为出错了。
- 挂上代理再测量一次。**我们这台机器上挂代理反而慢 0.3 秒**（0.79～0.80 秒），所以先量再决定。
- 只测了一台机器、一条宽带。换网络要重测。

## 卡 2 · 装完先跑 `netcheck`

**命令**：

```bash
tailscale netcheck
```

**我们看到的**（摘两行）：

```
* UDP: true
* Nearest DERP: Seattle
* DERP latency: sea: 170.9ms  sfo: 173.7ms  lax: 174.2ms
```

**容易出错的三件事**：

- **`Nearest DERP` 报出境外城市名不是故障**，是这台机器上的正常状态，不要为了这一行做额外操作。
- **数字每次跑都不一样**。同一条 `netcheck` 换个时间再跑就是另一组毫秒数（本章留档的那一次，最近的一站是 170.9 毫秒）。不要把单次结果当结论；同一件事至少跑两遍，并且**把每一遍的原始输出都存下来**。后半句是这本书后来补上的规矩：第 2 章早期版本引用过另一次的数字，但那一跑的原始输出没留档，所以 2026-10-14 把那些数字从正文和这份卡片里删掉了，改动记录在 `verify.md`。

## 卡 3 · 判断走没走中继：`tailscale ping`

**命令**：

```bash
tailscale ping <对端的 tailnet 地址>
```

**我们看到的两种形态**：

```
pong from <phone> (100.x.y.z) via <lan-ip:port> in 6ms         ← 同一个局域网，直连
pong from <phone> (100.x.y.z) via DERP(tok) in 320ms           ← 走流量了，绕代号 tok 的中继
direct connection not established                              ← 命令自己补的一句
```

**容易出错的三条（三条都实际遇到过）**：

1. **不要看错 `via` 后面的内容。** 是地址端口 = 直连；是 `DERP(地区)` = 走中继。这一眼决定你要不要继续排查。
2. **不要用普通 `ping`。** 普通 `ping` 走的不是 Tailscale 自己的通道，在这套网络里经常测不出真实情况，容易得出"连不上"的错误结论。
3. **`tailscale ping` 在直连没打通时退出码不是 0**，可是每一行 `pong` 照样打出来了。我们写脚本时在这条上失败过一次：程序只看退出码，认为命令失败了，把输出当异常抛了出来。**判断走没走中继要看输出内容，不要看退出码。**
