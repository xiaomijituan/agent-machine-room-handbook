# 国内网络差异 · 第 3 章

这一章讲多个 AI 一起干活，跟装软件关系不大，国内多出来的是**取包慢**和**出口可能根本不在**。

## 卡 1 · 装依赖前先确认源指向哪

**命令**：

```bash
npm config get registry
```

**实测到的**：

```
同一个包 left-pad，各测三次：
官方源   串行 2.01 / 1.05 / 0.94 秒      并发 0.96 / 1.29 / 2.55 秒
国内镜像 串行 0.047 ～ 0.081 秒          并发 0.073 ～ 0.081 秒
```

**坑**：

- **慢的不是"抢出口"**。三个并发并没有明显互相拖慢，官方源自己就抖（0.94 到 2.55 秒）。别为了"分流"去折腾多个终端。
- 镜像只快一个数量级这件事是真的，**但这次只测了一个很小的文件**。真装一次依赖（几百个请求、几十兆）差距会长什么样，我没测。
- 走镜像装包会把镜像地址写进 `package-lock.json`。队友从国外拉这份 lockfile 会连不上国内镜像。

## 卡 2 · 别引用别人的"通不通"，自己现量

**命令**：

```bash
curl -s -o /dev/null --max-time 8 -w "http=%{http_code} total=%{time_total}s\n" https://registry.npmjs.org/left-pad
```

**实测到的**：这次直连官方源**六次全部 200**，最慢 2.55 秒。

**坑**：我们自己以前的记录写着"官方源直连不通，必须走镜像"。**那条现在不成立。** 网络状态会变，所以正文和卡片都只写"这次量到什么"，不写"这个地址通不通"这种没有时间限定的结论。

## 卡 3 · 代理可能压根没开

**命令**：

```bash
netstat -ano | grep ":7897 " | grep LISTENING
curl -s -o /dev/null --max-time 10 -x http://127.0.0.1:7897 -w "http=%{http_code}\n" https://github.com
```

**实测到的**：

```
（netstat 那一条没有任何输出——7897 上没有进程在监听）
http=000        ← 走这个代理访问 github，连接失败
```

**坑**：多个 AI 一起干活时最容易查不清的一类问题是"某个工具配了代理，可代理没开"。表现是**卡在超时而不是报错**，AI 会重试、你会以为是 AI 慢。派活前先跑上面两条，十秒钟。
