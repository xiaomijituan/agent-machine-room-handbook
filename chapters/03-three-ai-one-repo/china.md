# 国内网络差异 · 第 3 章

第 3 章讲的是三个 AI 代理同时修改同一个仓库会产生的故障，与安装软件关系不大；国内环境多出来的是**取包慢**和**出口可能根本不在**这两层。

## 卡 1 · 安装依赖前先确认软件源指向哪里

**命令**：

```bash
npm config get registry
```

**实测到的**：

```
同一个包 left-pad，各测三次：
官方源   串行 2.01 / 1.05 / 0.94 秒      并发 0.96 / 1.29 / 2.55 秒
国内镜像 串行 0.047 ～ 0.081 秒          并发 0.073 ～ 0.081 秒
```

**要避开的错误**：

- **慢的原因不是"抢出口"**。三个并发请求并没有明显互相拖慢，官方源本身就会抖动（0.94 到 2.55 秒）。不必为了"分流"去开多个终端。
- 镜像比官方源快一个数量级，这一点是实测支持的；**但这次只测了一个很小的文件**。实际安装一次依赖（几百个请求、几十兆数据）时差距如何变化，没有测过。
- 通过镜像安装依赖会把镜像地址写进 `package-lock.json`；协作方从国外拉取同一份 lockfile，会连不上国内镜像。

## 卡 2 · 不要引用别人记录的"通不通"，要当场测量

**命令**：

```bash
curl -s -o /dev/null --max-time 8 -w "http=%{http_code} total=%{time_total}s\n" https://registry.npmjs.org/left-pad
```

**实测到的**：这次直连官方源**六次全部 200**，最慢 2.55 秒。

**要避开的错误**：我们先前的记录写着"官方源直连不通，必须走镜像"；**这句话现在不成立**。网络状态会变，所以正文和卡片都只写"这次量到什么"，不写"某个地址通不通"这类不带时间限定的结论。

## 卡 3 · 代理可能根本没有开启

**命令**：

```bash
netstat -ano | grep ":7897 " | grep LISTENING
curl -s -o /dev/null --max-time 10 -x http://127.0.0.1:7897 -w "http=%{http_code}\n" https://github.com
```

**实测到的**：

```
（netstat 那一条没有任何输出——7897 上没有进程在监听）
http=000        ← 走这个代理访问 github，连接失败
```

**要避开的错误**：多个 AI 代理同时工作时，最难查清的一类问题是某个工具配置了代理、而代理并未开启。表现是**停在超时而不是报错**，AI 会重试，你容易把原因归结为 AI 太慢。派发任务之前先执行上面两条命令，十秒钟就能测完。
