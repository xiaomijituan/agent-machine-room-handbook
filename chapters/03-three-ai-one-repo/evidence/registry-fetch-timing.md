# 多个活同时取包 · 实测证据

采集：2026-10-07，作者本人 Windows 机器（`core.autocrlf = true` 那台）。
工具：`curl`，同一个 URL 各测三次，再三个并发各测一次。

## 官方源

```
== 串行 3 次 ==
solo1  http=200 total=2.009865s
solo2  http=200 total=1.047307s
solo3  http=200 total=0.941873s

== 并发 3 个 ==
par2   http=200 total=0.962511s
par1   http=200 total=1.294226s
par3   http=200 total=2.545798s
```

## 国内镜像

```
== 串行 3 次 ==
solo1  http=200 total=0.065780s
solo2  http=200 total=0.081366s
solo3  http=200 total=0.047282s

== 并发 3 个 ==
par1   http=200 total=0.080531s
par2   http=200 total=0.073096s
par3   http=200 total=0.077155s
```

## 这两组数字说了什么，没说什么

**说了**：官方源每次 0.94 ～ 2.55 秒，波动大；镜像每次 0.047 ～ 0.081 秒，稳定，快一个数量级。

**没说**：没有看出"三个请求互相抢出口"的现象。官方源并发时最长 2.55 秒，可串行时最长也有 2.01 秒——**这个差落在单次抖动里，不能算并发造成的**。所以本章不写"多个 AI 会挤同一个出口"这句话。

**样本限制**：一个文件（`left-pad`，很小）、一次会话、一台机器、一个网络。**真实装一次依赖是几百个请求、几十兆字节，情况会不一样**；这一组只支撑"官方源慢且抖、镜像快且稳"这一条。

## 还有一条被推翻的前提（重要）

写这一章前，我们的记录里写着"npm 官方源直连不通，必须走镜像"。**这次实测：直连是通的，六次全部 `http=200`。** 慢是真的，不通是假的。

同一时间测本机代理：`127.0.0.1:7897` **没有进程在监听**，走它访问 github 得到 `http=000`（连接失败）。也就是说这台机器此刻没开代理——**"必须挂代理"这类话以后一律先量再说**。
