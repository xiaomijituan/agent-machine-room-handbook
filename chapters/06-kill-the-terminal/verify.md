# 第 6 章验证记录

## 机器（在哪台机器上量的）

- 一条 Linux 实验机：Ubuntu 22.04.5 LTS，内核 `5.10.134-18.0.12.lifsea8.x86_64`，
  `nproc` 为 4，内存 8192 MB，以 root 运行；实际形态是 Kubernetes 容器（PID 1 为沙箱运行时）。
  主机名、内网地址与容器标识已在入库前按格式替换，见"涂改"一节。**nohup、tmux 两格在这台上量。**
- 第二台机器（2026-10-09 加，为了量前台那一格）：一台阿里云 ECS，CentOS 8，内核
  `4.18.0-305.3.1.el8.x86_64`，`nproc` 为 2，内存 2 GiB，以 root 运行；`sshd` 在
  （`/usr/sbin/sshd`），**`tmux` 没装**。进出的通道是厂商自带的网页终端，不是本机 ssh 客户端。
  公网 IP、私网 IP、实例号与主机名按格式替换，见"涂改"一节。
- 模拟器那一局跑在本机（Windows 10 26200，x86_64），浏览器内离线单文件模拟器。

## 版本（跑的是什么版本）

- tmux 3.2a（**本来就装着**，所以"apt 装上 tmux"这一步证明不了任何事，没写成结论）。
  第二台机器（阿里云 ECS）**没装 tmux**，所以 tmux 那两格只在第一台机器上量过。
- `nohup`、`script`、`timeout` 均为系统自带（两台机器都在：第一台 `/usr/bin/`，第二台同样在 PATH 里）。
- 模拟器：fusion `0.1.2`；剧本 `amr-ch06-kill-the-terminal` 版本 `0.1`。

## 测到了什么（等级 A，本机/本环境可复现）

| 结论                                                       | 依据                                                                                                                                |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `nohup` + `disown` 起的进程在原来那个 shell 退出之后继续跑 | 日志 13 行 → 21 行；`ps -ef` 里父进程已是 1                                                                                         |
| tmux 会话在被"掐断伪终端"之后仍然存在，日志继续涨          | attach 退出码 124（timeout 杀掉的），之后 `tmux ls` 仍是同一条会话、同一创建时间；日志 6 行 → 23 行                                 |
| 会话只有被 `kill-server` 才消失                            | `kill-server` 之后 `tmux ls` 报 no server running，退出码 1                                                                         |
| 前台跑的循环在伪终端被关闭时停住，并变成僵尸               | 第二台机器：日志停在 4 行、末行时间戳就是掐断那一秒；3 分钟后重连，`ps -ef` 显示 `[ticker.sh] <defunct>`，`wc -l` 隔 3 秒两次都是 4 |
| 这台实验机不能被另一台连进来                               | 无 sshd（`ls` 报不存在）、监听端口里没有 22、没有 tailscale                                                                         |

## 没测到什么（这一章不许被读成结论的部分）

1. **真的断网之后进程还在不在**：这台机器做不到，做到就等于把自己杀掉。正文里那一条只写了
   "没有证据"，没写"没事"。
2. **两台真实设备之间的连接与跨网往返**：沙箱不是第二台设备（见上一条表格最后一行）。
3. **`nohup` 在第二台机器上没做成对照组**：那条 `nohup ./ticker.sh nh &` 连输出文件都没创建出来，
   进程在"已经 fork、还没执行到 `nohup`"这一瞬间被挂起信号打掉了——伪终端关得太快。**所以"nohup 能
   活下来"只有第一台机器那一个来源（13 行涨到 21 行），没有第二台复现**；正文也没把它写成"nohup 会死"。
4. **"关掉网页终端标签页"不等于"服务器侧断连"**：重连后 `who` 里 `pts/0` 还在，`timeout` 和 `script`
   两个进程还挂在它上面。所以"我掉线了，远端的活会不会死"这一格**从这个入口测不出来**，要用真 ssh 客户端
   掐连接再量。
5. 本章**配图已补上**（`assets/three-screens-three-fathers.svg`）：图是示意图，每个元素都取自本章正文与
   `scenario.json` 已经写明的东西（三块屏各自的上级进程、日志 13 行涨到 21 行、日志 6 行涨到 23 行、
   `kill-server` 才让会话消失、前台那一格标着"在另一台机器上量到了：日志停在第 4 行，进程变僵尸"），
   图上没有新增任何实测结论。**没测到的是配图本身的可读性**：没有请读者只看图复述结论，
   也没在不同屏幕宽度下验过。
6. 证据文本是**从聊天里贴回来的，不是沙箱那份原文件**：逐字性依赖那次复制，没做过与原文件比对。
   第二台机器那一段是操作者从网页终端里读出来的，同样没跟服务器上的原文件比对过。

## 等级（每条结论的可信度）

- A（本机/本环境可复现）：nohup 存活、tmux 会话存活、`kill-server` 才消失、这台机器不可被连入、
  前台循环在伪终端关闭时停住并变成僵尸（第二台机器）。
- B（模拟器里真跑，但点击是脚本合成、导出未经文件系统）：`reference.jsonl` 那一局。
- C（他人报告）：无。
- D（推断）：断网那一条明确标注为"没量到"，不给等级。正文第一段"终端窗口关掉时内核向前台进程组发
  挂起信号"仍是通用机制陈述——量到的是**用 `script` 造的伪终端被关闭**这一种情形，两者等价与否是
  推的解释，不是同一件事。
