# 断连实验 · 三格各自的下场（2026-10-12）

**这一份补的是第 6 章最后那一格**：客户端掉线的时候，前台直跑、`nohup` 分离、tmux 会话这三种起法，
各自的活还在不在。前两种此前只有一台机器上的来源，这一轮三种都在**同一台能被连进来的机器**上测量到了。

## 环境与做法

| 项目     | 值                                                                  |
| -------- | ------------------------------------------------------------------- |
| 远端机器 | 一台阿里云 ECS（CentOS 8.4.2105，2 核 2G，`sshd` 在，开机 1013 天） |
| 客户端   | 作者的 Windows 机器，OpenSSH 8.8p1                                  |
| tmux     | 这一轮现装的 `tmux 2.7`（机器上原本没有，`screen` 也没有）          |
| 工作目录 | `/root/amr-ch06-take2/`（本轮新建，实验后删除）                     |
| 被观察的 | 一条每秒钟往日志写一行的循环，每行前缀是**服务器自己的** `HH:MM:SS` |

**掐的是客户端这一侧**：用 Windows 的 `Stop-Process -Force` 结束那一条 `ssh.exe`。不碰服务器网络、
不碰本机网络配置、不拔网线。`ssh.exe` 一死，TCP 连接被重置，服务器上的 `sshd` 立刻发现会话没了。

每一格都跑同四步：**起 → 确认日志已经在长 → 掐 → 等 60 秒重连读回**。

## 探针自检：先证明"真的断开了"

这一道不做，后面所有"还活着"都是空话。三格都做了同一个检查——**掐完之后，`who` 里那条会话必须消失**：

```
格子 a 掐之前：
root     pts/0   2026-10-12 19:01 (<厂商内网地址>)     ← 厂商网页终端，一直在
root     pts/1   2026-10-12 19:12 (203.0.113.26)     ← 本次实验的会话
本机 ssh.exe 已启动，PID=34612
已在 19:12:45 用 Stop-Process 强制结束 PID=34612
本机还在跑的 ssh.exe 数：0
掐之后（服务器时间 19:12:48）：
root     pts/0   2026-10-12 19:01 (<厂商内网地址>)     ← pts/1 没了，断连成立
```

格子 b、c 的自检输出同样通过（`Stop-Process` 后本机 `ssh.exe` 数为 0，`who` 里 `pts/1` 消失）。

## 第一轮作废（值得记下来的一个坑）

第一次跑用的是 Git Bash 里 `ssh ... &` 再 `kill -9 $!`。结果**三份日志全都一路涨到实验结束**——
`kill -9` 杀掉的是 Git Bash 里的那个壳，`ssh.exe` 根本没死，服务器从头到尾没断过连。
那一轮的 `ps` 还留下另一个线索：远端循环的终端列是 `?`，说明伪终端压根没配上。
**换成 Windows 自己的进程管理（`Start-Process -PassThru` 拿 PID、`Stop-Process` 结束）之后，
自检才通过。** 教训：**掐客户端的实验，必须先证明客户端真的没了**，否则"活下来了"这句话
是探针自己造的。

## 三格的结果

| 格子             | 掐的时刻 | 掐时日志 | 60 秒后读回  | 断连那 60 秒里写了几行 | 相邻两行最大间隔 | 还在跑吗 | 上级进程      | 终端列  |
| ---------------- | -------- | -------- | ------------ | ---------------------- | ---------------- | -------- | ------------- | ------- |
| 前台直跑         | 19:12:45 | 12 行    | **仍 12 行** | 0 行                   | —                | 否       | —             | —       |
| `nohup`+`disown` | 19:15:13 | 12 行    | 74 行        | 64 行                  | 1 秒             | 是       | 1             | `?`     |
| tmux 会话        | 19:13:59 | 12 行    | 74 行        | 63 行                  | 2 秒             | 是       | tmux 服务进程 | `pts/2` |

三份日志的最后状态（实验结束时读回，此时 b、c 已各跑 259 行、185 行）：

```
===== a.log 共 12 行 =====
19:12:31 tick=1
   ...
19:12:41 tick=11
19:12:42 tick=12          ← 掐在 19:12:45，日志停在这里
===== b.log 共 259 行 =====
19:13:45 tick=1
   ...
19:17:24 tick=219
19:17:25 tick=220         ← 断连期间没有断档，最大间隔 2 秒
===== c.log 共 185 行 =====
19:15:00 tick=1
   ...
19:17:23 tick=144
19:17:24 tick=145
```

60 秒后重连时看到的进程表（格子 b 与 c 的活都还在）：

```
$ ps -eo pid,ppid,tty,stat,etime,cmd | grep 'ticke[r].sh'
2938374       1 ?        Ss   03:40  tmux new -s ch06b ./ticker.sh b.log
2938375 2938374 pts/2    Ss+  03:40  /bin/bash ./ticker.sh b.log
2942528       1 ?        S    02:25  /bin/bash ./ticker.sh c.log

$ tmux ls
ch06b: 1 windows (created Mon Oct 12 19:13:45 2026) [80x23]
```

三行读法：`b.log` 那行的上级是 `2938374`（tmux 的服务进程），终端是 `pts/2`——**不是我们掐掉的那条
`pts/1`**，是 tmux 自己给的一块伪终端；`c.log` 那行上级是 `1`、终端列是 `?`，也就是"改登记给了
机器上编号 1 的总管家进程、并且已经没有终端可挂"。**前台那一格 60 秒后 `ps` 里什么都查不到。**

## 这一轮把上一轮留下的两个洞补上了

1. **`nohup` 对照臂这次做成了**。上一轮它连输出文件都没创建出来（伪终端关得太快，进程在"已经 fork、
   还没执行到 `nohup`"那一瞬被挂断信号打掉）。这一轮改成**先确认日志已经写出 12 行再掐**，
   `c.log` 就正常地活过了断连。上一轮那句"`nohup` 能活下来只有一台机器上的一个来源"现在作废：
   有两个来源了。
2. **不再从网页终端入口测**。上一轮测量到"关掉网页终端的标签页，服务器侧连接根本没断"（`who` 里
   `pts/0` 还在），所以那一格当时判为"从这个入口测不出来"。这一轮用的是真 `ssh` 客户端 +
   结束客户端进程，自检显示会话确实消失，才得到上面的表。

## 这一轮**没有**测到的

- **真·断网（拔网线、关 Wi-Fi、路由器掉电）没做。** 结束 `ssh.exe` 会让 TCP 连接被重置，
  `sshd` 几乎立刻发现；真断网时没有那个重置包，`sshd` 可能要等到自己的超时或 keepalive 才发现，
  前台进程收到挂断信号的**时点会更晚**（会不会最终也死，这一轮没有测量）。
- **前台那一格这次没留下僵尸进程**。上一轮（同一台机器、走网页终端入口）测量到 `[ticker.sh] <defunct>`；
  这一轮 60 秒后 `ps` 里查不到任何残留。差别可能出在父 shell 有没有来得及回收，**没做对照，
  所以只报现象，不给解释**。
- **`tmux 2.7` 是这一轮现装的**，跟第 1 章那台沙箱里的 `tmux 3.2a` 不是同一个版本。
  本章结论不涉及版本差异的功能，但版本写在这里，供复现时对齐。
- **只测了一台远端机器、每格一次**，没有重复三轮。间隔统计（1 秒、2 秒）来自单次运行的日志。

## 如何复跑

服务器侧准备（在 `/root/amr-ch06-take2/` 里放一个 `ticker.sh`：每秒 `printf '%s tick=%d\n' "$(date +%H:%M:%S)" $n >> $1`），
再加三个包装脚本：`arm-a.sh` 前台跑、`arm-b.sh` 用 `tmux new -s ch06b` 跑、`arm-c.sh` 用
`nohup … & disown` 跑。客户端侧的驱动脚本是 `run-take2.ps1`（PowerShell，`Start-Process -PassThru`
拿 PID、`Stop-Process` 掐、每步用一条独立 `ssh` 读回 `wc -l`、`tail -1`、`who`、`tmux ls`、`ps`）。
**注意第一轮失败的原因**：Git Bash 里 `ssh &` 加上 `kill -9 $!` 掐不掉真正的 `ssh.exe`。
