# 第 9 章 · 国内网络环境下的差异卡片

| 操作                                   | 你会看到什么                                                       | 坑在哪                                                                                                                               |
| -------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 把工具发成 npm 包，等国内装            | 新包在 npmmirror 上同步之前，`npm install` 会慢或者装不到旧镜像    | 这是这一章选择"发布页附单文件产物"的三条理由之一（另两条：要占包名、要跟自己的发布节奏解耦）。零安装的一条 `curl` 绕开了整层同步等待 |
| 本机 `curl` GitHub 发布接口            | 2026-10-10 第一次请求返回 `http=000`（代理没通），重试第二次才 200 | `000` 是**连不上**，不是"没有这个版本"。分不清就会去改 URL，而 URL 一直是对的                                                        |
| 本手册 CI 里那一步"下载 fusion 的产物" | 在 GitHub 的境外机器上跑，一次约 1 秒                              | **CI 下载不受你家宽带影响**；受影响的是你"本地下回来核对"那一步。把两边混起来，会误判成"产物有问题"                                  |
| 双击 `fusion-sim-<版本>.html` 开机房   | 不联网就能跑：JS 与 CSS 全在一个文件里，页面里零外部请求           | 这条对国内是实打实的价值：**不依赖任何 CDN**。反面教训是别把它做成 zip——zip 只是把同一个文件藏起来，白拿一次解压                     |

一句提醒：上面四条里，第一条和第三条是**设计记录与 CI 配置里写明的取舍**（为什么这么选），
第二条是本机实测（同一句请求两次结果不同），第四条是走查项盯着的性质。
**产物在慢网上下载要多久，没测过**——404,823 字节这个数是本机读到的，不是网速测量。
