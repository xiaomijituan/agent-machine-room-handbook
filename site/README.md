# site/ —— 本地阅读与试玩用的壳

这个目录里只有三个文件：一个章节页面、一个目录页、一个静态服务器。它们只服务于本地阅读，不部署到任何地方，也不联网获取任何东西。

## 怎么跑

```bash
npm run serve:site          # 默认 http://127.0.0.1:5280
node site/serve.mjs 8000    # 想换端口就带上端口号
```

服务器只监听 `127.0.0.1`，不对外开放；它只会返回这个仓库里的文件，路径想跑到仓库外面会被拒绝。

打开这些地址：

- 目录页：<http://127.0.0.1:5280/site/>
- 第 1 章：<http://127.0.0.1:5280/site/chapter.html?chapter=01-one-screen-many-ai>

## 页面是怎么工作的

`site/chapter.html` 做三件事：

1. 从地址栏的 `?chapter=` 参数里取章节目录名，去读 `chapters/<章节目录名>/scenario.json`。
2. 用 iframe 装载 `vendor/fusion-sim-0.1.2.html`，然后用 `postMessage` 把本章的剧本原文交给这个被装载的模拟器页面。消息格式由 fusion 定义（见 fusion 的 ADR-0008）：

   ```jsonc
   // 章节页 → 模拟器（只允许这两个字段）
   { "type": "fusion:load-scenario", "scenario": "<剧本 JSON 的原文字符串>" }
   // 模拟器 → 章节页
   { "type": "fusion:load-scenario-result", "ok": true, "errors": [], "warnings": [] }
   ```

3. 把回执里的内容原样写到页面顶部的状态行。`errors` 是模拟器给出的中文校验说明，`warnings` 是"装进去了但有话要说"（例如替换了同名的旧剧本）。页面只显示文本，不会把回执里的内容当成 HTML 解释。

模拟器在启动的过程中才装上接收消息的监听器，所以发早了会被丢掉。章节页因此每 500 毫秒重发一次，最多 20 秒；等到回音就停，等不到就提示读者改用手工粘贴（页面下方留了剧本原文和粘贴步骤）。

## 本目录的通用页与生成出来的章节页有什么区别

`npm run build:site`（脚本在 `tools/build-variants.mjs`）会为每一章生成一个独立页面，落在
`output/site/<章节目录>.html`。两者用的是同一套注入机制，区别在两处：

| 页面                              | 章节怎么定               | 剧本从哪来                            | 用途                           |
| --------------------------------- | ------------------------ | ------------------------------------- | ------------------------------ |
| `site/chapter.html`（本目录）     | 地址栏的 `?chapter=`     | 运行时 `fetch` 该章的 `scenario.json` | 改正文或改剧本时随手刷新       |
| `output/site/<章节>.html`（产物） | 文件名已经定死，不用参数 | 构建时就把 JSON 写进页面              | 发给别人看的那一份，能直接打开 |

产物页里还带着本章正文渲染出来的 HTML，所以它是一个完整的"读 + 玩"页面；本目录的通用页只负责玩。
两个版式（站点版 HTML 与掘金版图文）都由那条命令生成，理由写在仓库根部的 `README.md` 里。

## 这份东西是怎么验的（证据等级：本地可复现）

验证方法：用 Playwright 打开页面，读页面里的状态行和 iframe 里的机房格子。下面每一条都在 `http://127.0.0.1:5280` 上跑过。

| 检查                              | 结果                                                                                                                            |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 首次进入第 1 章，剧本有没有被接受 | 状态行显示"剧本已装入"，三次全新会话分别在 0.80、0.83、0.84 秒内完成                                                            |
| 机房是否换成本章的样子            | 格子数从出厂的 16 变成 3，主机一栏是 `laptop,cloud`                                                                             |
| 重复交同一份剧本会不会悄悄覆盖    | 状态行多出一行提醒：`id: 已替换同名剧本「amr-ch01-three-screens」。`                                                            |
| 故意交一份写坏的剧本              | 状态行显示 `panes[0].host: 找不到主机「ghost」。本剧本的主机有：laptop、cloud。`，机房仍然是 3 格，没有跟着换                   |
| 是否真的离线                      | 整个过程中一共只有 3 个请求，全部指向 `127.0.0.1:5280`（页面本身、模拟器文件、本章剧本）。指向互联网任何一个地址的请求都是 0 个 |

验证过程中抓到两个自己的错，一并记下，免得以后再犯：

1. 状态行的写入函数只接受字符串数组，我按字符串传参，抛出的异常把整条注入流程打断，页面一直停在"模拟器正在加载"。
2. 重发逻辑里我把"清掉定时器"写进了发送函数，于是第一次发送之后定时器就被自己取消，等于整个流程只发了一次。而那一次恰好落在模拟器还没装上监听器的时候，消息被丢掉，页面就永远等不到回音了。上面那段"每 500 毫秒重发、20 秒后放弃"就是为了不再依赖运气。
