# agent 机房手册

**《agent 机房手册》** —— 一本中文的、能照着做的教程：让几个 AI 一起干活的时候，你的机器该长什么样。

这不是编排工具，是教材。每一章都对应机房里的一个真实时刻，配一个能点的剧本、一份跑出来的记录、一份验证记录。

## 每章为什么有五个文件

| 文件              | 作用                                                                   |

| `index.md`        | 正文。纯 Markdown，能整段复制到掘金而不散架                            |
| `scenario.json`   | 可玩剧本，粘进模拟器就能玩                                             |
| `reference.jsonl` | 我们真跑出来的一局记录，用来跟你那一局对拍                             |
| `verify.md`       | 验证记录：在哪台机器、什么版本、测到什么、**没测到什么**、涂改了哪几处 |

**读某一章之前先看它的 `verify.md`**。哪句话是量出来的、哪句话只是经验，那张表里写着。

## 怎么玩剧本

每一条能动手的内容都配了一份剧本（该章的 `scenario.json`）。玩它有两种方式，走的是同一套校验：

```bash
npm install --registry=https://registry.npmmirror.com
npm run serve:site     # 起一个只监听 127.0.0.1 的本地页面
```

打开 <http://127.0.0.1:5280/site/>，选一章进去，页面会把这一章的剧本交给嵌在下面的模拟器，机房随之变成剧本里描述的样子。这个方式不用联网：仓库的 `vendor/` 里就放着模拟器的一份复制件（fusion 的 `v0.1.2`，来历和校验和写在 `vendor/README.md`）。

另一种方式是手工粘贴：自己打开模拟器，进「剧本库」，把该章 `scenario.json` 的全文粘进输入框，按「导入」。

模拟器本身叫 fusion（聚变），仓库在 <https://github.com/xiaomijituan/fusion>。

## 本地检查

```bash
npm install --registry=https://registry.npmmirror.com
npm run check        # 五件套、署名行、相对链接、记录文件的事件行合法且与同一章的剧本对得上、验证记录完整性、身份掩码、复制件与页面是否对得上
npm run format       # 格式化（vendor/ 里的第三方复制件不参与格式化）
```

`npm run check` 不需要联网。剧本字段和事件流格式的权威校验不在这里，在 fusion 发布的
`scenario-check.mjs` 与 `review-cli.mjs` 里，CI 会按写死的版本下载来逐章跑一遍
（见 [.github/workflows/ci.yml](./.github/workflows/ci.yml)）；这一步要联网，所以放在 CI 而不是本地钩子里。

## 两个版式怎么产出

同一份正文要发两个地方：自己的站点（能点）和掘金（只能图文，掘金会把 iframe 与原始 HTML 过滤掉）。
所以两个版式都不靠手抄，由一条命令从同一份 `index.md` 生成：

```bash
npm run build:site
```

它读每章的三份文件（`index.md`、`scenario.json`、`reference.jsonl`），产出两份东西：

- `output/site/<章节目录>.html` —— 站点版。正文渲染成页面，页面下方嵌着 `vendor/` 里那份模拟器，
  本章的剧本直接写在页面里递给它，不需要查询参数。**这一层目录就是公网部署的东西**：
  <https://xiaomijituan.github.io/agent-machine-room-handbook/>，由
  `.github/workflows/pages.yml` 在每次合进 `main` 时构建并发出去。页面里的路径全部相对
  `output/site/` 这一层（本章配图复制进 `output/site/assets/<章节目录>/`，模拟器复制件在
  `output/site/vendor/`），所以站点挂在 `/agent-machine-room-handbook/` 这种子路径下不用改任何东西。
  本地看：先 `npm run serve:site`（只监听 127.0.0.1:5280），再打开
  <http://127.0.0.1:5280/output/site/01-one-screen-many-ai.html>。
  这一步要等模拟器回话，最慢约一秒；递不进去时页面下方有"注入失败怎么办"，把本章剧本原文摊开
  供手工粘贴。
- `output/juejin/<章节目录>.md` —— 掘金版。正文原样保留（一个字都不改），文末追加三段：
  一张决策表、一段"想自己点这里"（指向上面那个公网地址，因为掘金会把交互内容过滤掉）、
  一份可复制的剧本全文。决策表由 fusion 发布的 `review-cli.mjs` 从该章的 `reference.jsonl`
  投影而来，本仓库不再另写一份投影规则。

掘金版过三道守卫，任何一道不过，`npm run build:site` 就以退出码 1 结束：产物里搜不到 `<iframe`
和 `<script`；外链只允许落在 `github.com`、`127.0.0.1`、`localhost`、本仓库自己的 Pages 地址和
Tailscale 官方那几个域名上——白名单里唯一的部署实例就是我们自己发出去的那个，别的主机出现就说明
有人把链接指到了临时地址；决策表和当场再跑一次投影器的结果逐字相同。

正文里的配图是各章目录下的 SVG（例如 `chapters/01-one-screen-many-ai/assets/one-screen-per-agent.svg`），
只允许相对路径，不接受远程图片——掘金那一版带不走外部资源。站点版会把相对路径改写成从产物页
能走到的真实位置，浏览器实测过图片确实加载出来。

### 掘金那一版怎么带图（2026-10-10 第 2 章首发实测）

**一句话：仓库里的 SVG 不能当图传给掘金，要传本地渲染的 2 倍 PNG。** 下面八条都是那一次上传里
真看到的，不推。入口先说清楚：编辑器只能从 创作者中心 → 写文章 进去，未登录直接访问编辑器地址会被
弹回首页；草稿自动保存，编辑器右上角的状态字样是"保存成功"。

1. 掘金的插图控件没有设 `accept` 过滤，SVG 选得上、也传得上去——但传上去不等于显示得对。
2. 掘金在服务端把 SVG 转成位图（返回的图片地址结尾是 `.awebp`），而转码机上没有中文字体：
   SVG 里的中文全部变成方框。所以 SVG 在掘金只能作为"数据"给读者下载，不能作为"图"发布。
3. 同一张图渲染成 2 倍 PNG（第 2 章那张是 2000×1440）再上传，中文完整、线宽正常、显示尺寸正确。
   渲染必须在装了中文字体的机器上做——第 2 条已经证明掘金的转码机没装。
4. 上传后的每张图右下角都被烧进水印"掘金技术社区 @ 作者账号名"，去不掉。配图里如果截进了真实
   主机名或账号名，要在上传之前自己处理掉：本仓库的掩码规矩由 `scripts/check.mjs` 守的是入库文本，
   管不到掘金上那张位图。
5. 表格活着。第 2 章那版一共 4 张表：正文里 3 张（8 行 2 列、5 行 4 列、4 行 3 列），文末由投影器
   追加的决策表 1 张（4 行 6 列）。预览里四张的边框都在，最宽的 6 列那张没有塌成纯文本。
6. 代码块不折行。掘金给代码块的样式是 `white-space: pre`，长命令在块内横向滚动而不是被折断。
   第 2 章最宽的一行 587 像素，手机可用宽约 358 像素，所以手机上看到的是一行能左右推的命令。
   风险在横向滚动不明显：正文里的命令行建议控制在 60 个字符以内。
7. 文章标题字段和正文首行的 H1 会各显示一遍，同一句话在页面上出现两次大标题。所以粘贴版删掉正文
   首行的 H1，章号改写进导语那句完整的话里；文末追加的复盘段同样从 H1 降成 H2，这一步在
   `tools/build-variants.mjs` 里做。
8. 首页卡片上的"介绍"不是单独填写的字段，而是**从正文开头截出来的**，实测截断在 100 个字。
   署名行（`> © 2026 …`）自己就占 120 个字，留在开头等于把导语的位置全占掉。所以粘贴版把署名行
   挪到文末，并在最前面留一行导语占位；写导语照旧用手册的规矩：把量到的数字放进前 40 个字。
9. 发布面板（点右上角「发布」弹出）里有六栏：分类、添加标签、文章封面、收录至专栏、创作话题、
   编辑摘要。带星号的是**分类、添加标签、编辑摘要**三项。摘要那一栏确实是可手写的输入框，上限
   100 字，默认值就是第 8 条说的那段硬截的正文开头——所以要在点发布之前把它改写成一句完整的话，
   不然卡片上会出现半句。
10. 标签只能选掘金已有的。实测 `tmux`、`Tailscale`、`运维`、`VPN` 这四个词在标签搜索里没有候选
    （接口打的是 `tag_api/v1/query_tag_list`，返回空），`Linux` 有。所以别指望用标签精确描述本章，
    挑一个最接近的现有标签即可。创作话题是一组固定的活动（实测 10 条，最多选 1 条），不是自由输入。
11. 面板里的「收录至专栏」只能搜已有专栏，**没有创建入口**。建专栏要走去：创作者中心 → 专栏管理 →
    新建专栏（名称上限 50 字、简介上限 150 字、封面建议 480×270），提交后提示"新建专栏需要一定的
    审核时间"。专栏建好之后，用专栏页的「添加文章」把已发的文章收进去。
12. **发出去不等于发得出去。** 第 2 章这一篇 2026-10-10 20:52 提交，判为"审核未通过"：公开地址
    `/post/<文章号>` 返回 404，只有作者预览 `/spost/<文章号>` 能打开，标题旁边挂一个红色"审核未通过"
    标记。掘金**没有给出原因**——文章管理列表里只有状态两个字，系统通知和私信里都没有说明文案，
    预览页上那个「前往申诉」的按钮实测是隐藏元素（`getBoundingClientRect()` 是 0×0，点不到）。
    所以"掘金会不会告诉你为什么拒"这一条，答案是：找过，没找到入口。

一条命令产出粘贴版：

```bash
npm run build:site
npm run juejin:paste -- 02-tailscale-china-relay    # 写到 output/juejin-paste/ 下
```

粘贴版只做上面第 1、7、8 条逼出来的三处渠道改动（删正文首行 H1、把署名行挪到文末、把配图换成插图
标记），正文一个字不动。改完它自己复检：还剩 H1、署名行不在文末、配图路径还是相对路径、插图标记
丢了——这四种情况都会以退出码 1 报出来，不会交出一份看着齐了其实少了东西的稿子。配图渲染成 PNG
那一步没有写进仓库：它要的无头浏览器不在本仓库依赖里（CI 只跑文本检查，装上纯属浪费），而且那一步
必须在装了中文字体的机器上跑，读者的机器才是正确的现场。

**还没测的**：审核未通过的具体触发条件（改哪一处能过，没验过，不做猜测性修改）；标签与分类对推送量
的影响；配图在深色模式下的表现。

`output/` 是产物目录，不入库。构建需要 `.fusion-tools/review-cli.mjs` 在场（那是 fusion 按版本号发布的
那份投影器，CI 会自己下载；本地缺了它会以退出码 2 结束并把下载命令原样打给你）。

## 这个仓库的三条硬规矩

写正文之前先读 [STYLE.md](./STYLE.md)，改任何东西之前先读 [GLOSSARY.md](./GLOSSARY.md)：

1. **不用回指词**。"它 / 那个 / 前者 / 后者"一律换成具体名词，别让人回头找指代。
2. **词表外的术语第一次出现当场解释**。括号里说人话。
3. **测到的和推出来的分开写**。没复现的结论标"没测到"，并列出验证命令。

还有一条流程上的：**证据入库前必须涂掉身份信息**（公网 IP、内网地址、主机名、账号）。每章的 `verify.md` 要列出涂了哪几处。

## 许可

分两层，因为"代码被复制"和"文章被搬运"是两件事：

- **正文**（各章 `index.md`、`verify.md`、`china.md`，README、STYLE、GLOSSARY、AGENTS）——**CC BY 4.0**，见 [LICENSE-docs.md](./LICENSE-docs.md)。署名方式与"不得暗示背书"在那份文件里指定了。
- **代码与数据**（`scripts/`、`tools/`、各章 `scenario.json`、`reference.jsonl`）——**MIT**，见 [LICENSE](./LICENSE)。

**每章开头那一行署名是硬要求**，`npm run check` 会查它在不在。原因很实际：MIT 的署名要求只在"跟着文件走"时才有效，而整章被复制到别处时不会带上 LICENSE 文件——署名必须长在正文里。

**一句实话**：CC BY 4.0 允许别人商用，所以这些文字可以被别人免费转发到他的网站，本仓库接受这个后果。付费版本的价值在于成体系的编排、可玩的剧本、练习和维护，不在于禁止转发。

## 一句提醒

别把模拟器挂在后台标签页。浏览器会限速看不见的页面——我们实测三分钟里，模拟器里的一拍时钟只走了 6 格，正常差不多一秒一格。
