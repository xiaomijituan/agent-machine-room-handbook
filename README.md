# agent 机房手册

**《agent 机房手册》** —— 一本中文的、能照着做的教程：让几个 AI 一起干活的时候，你的机器该长什么样。

这不是编排工具，是教材。每一章都对应机房里的一个真实时刻，配一个能点的剧本、一份跑出来的记录、一份验证记录。

## 每章为什么有五个文件

| 文件              | 作用                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| `index.md`        | 正文。纯 Markdown，能整段复制到掘金而不散架                            |
| `scenario.json`   | 可玩剧本，粘进模拟器就能玩                                             |
| `reference.jsonl` | 我们真跑出来的一局记录，用来跟你那一局对拍                             |
| `verify.md`       | 验证记录：在哪台机器、什么版本、测到什么、**没测到什么**、涂改了哪几处 |
| `china.md`        | 国内网络差异卡片：命令 → 我们看到的 → 坑                               |

**读某一章之前先看它的 `verify.md`**。哪句话是量出来的、哪句话只是经验，那张表里写着。

## 怎么玩剧本

每一条能动手的内容都配了一份剧本（该章的 `scenario.json`）。玩它有两种方式，走的是同一套校验：

```bash
npm install --registry=https://registry.npmmirror.com
npm run serve:site     # 起一个只监听 127.0.0.1 的本地页面
```

打开 <http://127.0.0.1:5280/site/>，选一章进去，页面会把这一章的剧本交给嵌在下面的模拟器，机房随之变成剧本里描述的样子。这个方式不用联网：仓库的 `vendor/` 里就放着模拟器的一份复制件（fusion 的 `v0.1.2`，来历和校验和写在 `vendor/README.md`）。

另一种方式是手工粘贴：自己打开模拟器，进「剧本库」，把该章 `scenario.json` 的全文粘进输入框，按「导入」。

模拟器本身叫 fusion（聚变），仓库在 <https://github.com/xiaomijituan/fusion>。

## 本地检查

```bash
npm install --registry=https://registry.npmmirror.com
npm run check        # 五件套、署名行、相对链接、记录文件的事件行合法且与同一章的剧本对得上、验证记录完整性、身份掩码、复制件与页面是否对得上
npm run format       # 格式化（vendor/ 里的第三方复制件不参与格式化）
```

`npm run check` 不需要联网。剧本字段和事件流格式的权威校验不在这里，在 fusion 发布的
`scenario-check.mjs` 与 `review-cli.mjs` 里，CI 会按写死的版本下载来逐章跑一遍
（见 [.github/workflows/ci.yml](./.github/workflows/ci.yml)）；这一步要联网，所以放在 CI 而不是本地钩子里。

## 两个版式怎么产出

同一份正文要发两个地方：自己的站点（能点）和掘金（只能图文，掘金会把 iframe 与原始 HTML 过滤掉）。
所以两个版式都不靠手抄，由一条命令从同一份 `index.md` 生成：

```bash
npm run build:site
```

它读每章的三份文件（`index.md`、`scenario.json`、`reference.jsonl`），产出两份东西：

- `output/site/<章节目录>.html` —— 站点版。正文渲染成页面，页面下方嵌着 `vendor/` 里那份模拟器，
  本章的剧本直接写在页面里递给它，不需要查询参数。本地看：先 `npm run serve:site`（只监听
  127.0.0.1:5280），再打开 <http://127.0.0.1:5280/output/site/01-one-screen-many-ai.html>。
  这一步要等模拟器回话，最慢约一秒；递不进去时页面下方有"注入失败怎么办"，把本章剧本原文摊开
  供手工粘贴。
- `output/juejin/<章节目录>.md` —— 掘金版。正文原样保留（一个字都不改），文末追加两段：
  一张决策表和一份可复制的剧本全文。决策表由 fusion 发布的 `review-cli.mjs` 从该章的
  `reference.jsonl` 投影而来，本仓库不再另写一份投影规则。

掘金版过三道守卫，任何一道不过，`npm run build:site` 就以退出码 1 结束：产物里搜不到 `<iframe`
和 `<script`；外链只允许落在 `github.com`、`127.0.0.1`、`localhost` 和 Tailscale 官方那几个域名上，
出现别的主机就说明有人把链接指到了某个部署实例；决策表和当场再跑一次投影器的结果逐字相同。

正文里的配图是各章目录下的 SVG（例如 `chapters/01-one-screen-many-ai/assets/one-screen-per-agent.svg`），
只允许相对路径，不接受远程图片——掘金那一版带不走外部资源。站点版会把相对路径改写成从产物页
能走到的真实位置，浏览器实测过图片确实加载出来。发掘金时那一行图片语法会变成一张需要你自己上传的图：
掘金不认仓库里的相对路径，得把同一个 SVG 作为图片传上去。

**下面这五步一步都没走过**，是照着"掘金会过滤 iframe 与原始 HTML"这条已知规则推出来的操作顺序，
等第 2 章首发撞上问题时按实测结果改写这一节，别当成已验证的流程：

1. 跑 `npm run build:site`，打开 `output/juejin/<章节目录>.md`，确认那一行图片语法还在，
   一行以感叹号开头，方括号里是中文 alt，圆括号里是 `assets/` 下的相对路径。掘金版正文是逐字复制的，
   图也只会以这一行的形式出现。
2. 从 `chapters/<章节目录>/assets/` 里取出那个 SVG。**没测过掘金收不收 SVG**；不收的话要在本地转成
   PNG，而转换会不会把系统字体渲染成方框、会不会让 32 号字变糊，都没量过。
3. 在掘金编辑器里删掉那一行图片语法，把光标留在原来的位置，用编辑器的插图功能上传第 2 步那份文件。
   alt 文本在掘金里怎么呈现（显示成图注、还是吞掉）没测。
4. 发布前预览两件事：图前后的表格还是不是表格；图上的中文在掘金那版的实际显示尺寸有多大。
   这两条都没测，而第 4 条直接决定手机上看不看得清——本地站点版是按 390px 屏宽量过的（图占满 390px，
   图里最小字号折算下来 12.5px），掘金那版没有这个保证。
5. 发完之后，把看到的差别写进该章 `verify.md` 的"没测到什么"，并把这一节的五步改成实测记录。

`output/` 是产物目录，不入库。构建需要 `.fusion-tools/review-cli.mjs` 在场（那是 fusion 按版本号发布的
那份投影器，CI 会自己下载；本地缺了它会以退出码 2 结束并把下载命令原样打给你）。

## 这个仓库的三条硬规矩

写正文之前先读 [STYLE.md](./STYLE.md)，改任何东西之前先读 [GLOSSARY.md](./GLOSSARY.md)：

1. **不用回指词**。"它 / 那个 / 前者 / 后者"一律换成具体名词，别让人回头找指代。
2. **词表外的术语第一次出现当场解释**。括号里说人话。
3. **测到的和推出来的分开写**。没复现的结论标"没测到"，并列出验证命令。

还有一条流程上的：**证据入库前必须涂掉身份信息**（公网 IP、内网地址、主机名、账号）。每章的 `verify.md` 要列出涂了哪几处。

## 许可

分两层，因为"代码被复制"和"文章被搬运"是两件事：

- **正文**（各章 `index.md`、`verify.md`、`china.md`，README、STYLE、GLOSSARY、AGENTS）——**CC BY 4.0**，见 [LICENSE-docs.md](./LICENSE-docs.md)。署名方式与"不得暗示背书"在那份文件里指定了。
- **代码与数据**（`scripts/`、`tools/`、各章 `scenario.json`、`reference.jsonl`）——**MIT**，见 [LICENSE](./LICENSE)。

**每章开头那一行署名是硬要求**，`npm run check` 会查它在不在。原因很实际：MIT 的署名要求只在"跟着文件走"时才有效，而整章被复制到别处时不会带上 LICENSE 文件——署名必须长在正文里。

**一句实话**：CC BY 4.0 允许别人商用，所以这些文字可以被别人免费转发到他的网站，本仓库接受这个后果。付费版本的价值在于成体系的编排、可玩的剧本、练习和维护，不在于禁止转发。

## 一句提醒

别把模拟器挂在后台标签页。浏览器会限速看不见的页面——我们实测三分钟里，模拟器里的一拍时钟只走了 6 格，正常差不多一秒一格。
