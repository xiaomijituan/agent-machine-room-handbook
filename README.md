# agent 机房手册

**《agent 机房手册》** —— 一本中文的、能照着做的教程：让几个 AI 一起干活的时候，你的机器该长什么样。

这不是编排工具，是教材。每一章都对应机房里的一个真实时刻，配一个能点的剧本、一份跑出来的记录、一份验证记录。

## 每章为什么有五个文件

| 文件              | 作用                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| `index.md`        | 正文。纯 Markdown，能整段复制到掘金而不散架                            |
| `scenario.json`   | 可玩剧本，粘进模拟器就能玩                                             |
| `reference.jsonl` | 我们真跑出来的一局记录，用来跟你那一局对拍                             |
| `verify.md`       | 验证记录：在哪台机器、什么版本、测到什么、**没测到什么**、涂改了哪几处 |
| `china.md`        | 国内网络差异卡片：命令 → 我们看到的 → 坑                               |

**读某一章之前先看它的 `verify.md`**。哪句话是量出来的、哪句话只是经验，那张表里写着。

## 怎么玩剧本

下载模拟器的打包文件，打开里面的页面，进"剧本库"，把该章 `scenario.json` 的内容粘进去，导入。

模拟器叫 fusion（聚变），仓库在 <https://github.com/xiaomijituan/fusion>。

## 本地检查

```bash
npm install --registry=https://registry.npmmirror.com
npm run check        # 结构、剧本字段、记录文件、相对链接、验证记录完整性
npm run format       # 格式化
```

## 这个仓库的三条硬规矩

写正文之前先读 [STYLE.md](./STYLE.md)，改任何东西之前先读 [GLOSSARY.md](./GLOSSARY.md)：

1. **不用回指词**。"它 / 那个 / 前者 / 后者"一律换成具体名词，别让人回头找指代。
2. **词表外的术语第一次出现当场解释**。括号里说人话。
3. **测到的和推出来的分开写**。没复现的结论标"没测到"，并列出验证命令。

还有一条流程上的：**证据入库前必须涂掉身份信息**（公网 IP、内网地址、主机名、账号）。每章的 `verify.md` 要列出涂了哪几处。

## 一句提醒

别把模拟器挂在后台标签页。浏览器会限速看不见的页面——我们实测三分钟里，模拟器里的一拍时钟只走了 6 格，正常差不多一秒一格。
